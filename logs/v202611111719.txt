### S2 — 脚本改造（en，随后同步 zh）
- 参数: `DEVICE = sys.argv[1]`（`cpu`|`gpu`）、`PRECISION = sys.argv[2]`（`single`|`double`）；
  `REAL`/`COMPLEX` 按精度取 `float32/float64`、`complex64/complex128`，容差 `RTOL=1e-5/1e-12`
- 设备层: gpu 分支 `cupy.asarray` + `cp.cuda.Device(0).synchronize()`，并加 `to_host` 把对照结果取回；
  cpu 分支为恒等函数。`timed()` 与 `run_parallel()` 在 `init`/`run` 前后都做同步
- 进程数: `PROCS = 4 if DEVICE == "cpu" else 1` —— 自建池会把操作数落盘成 numpy，
  GPU 上多进程测的是 CPU，故 GPU 固定单进程（脚本注释与文档都写明）
- 输出: 开头打印 `pyqcd <ver> <file> | <device> | <precision> | procs N`（避免把旧安装当成新构建）
- 结果缓冲区: 保持 host 端 numpy（`init`/`run` 原地写入；自建池本就落盘 numpy），
  GPU 下 exec 含一次 D2H 拷贝，已在脚本 docstring 注明

批量基准脚本现在与 15-case 基准用同一套开关。

## 一、接口

```bash
python bench.py                 # 默认 = cpu single
python bench.py cpu single      # 单精度（float32 / complex64），rtol 1e-5
python bench.py cpu double      # 双精度（float64 / complex128），rtol 1e-12
python bench.py gpu single      # 设备端计时（cupy，带 synchronize）
```

- **设备**：`DEVICE = sys.argv[1]`，与 15-case 基准完全一致；gpu 分支负责
  `to_device` / `to_host` / `synchronise`，并在开头打印
  `pyqcd <版本> <文件路径> | <设备名> | <精度> | procs N`，避免把 site-packages 里的旧构建当成新版本。
- **精度**：`PRECISION = sys.argv[2]`，`single`/`double` 同时决定操作数 dtype 与对照容差。
- **GPU 的一个如实限制**：自建进程池会把每个操作数落盘成 numpy，所以 `gpu` 下进程数固定为 1
  （多进程测到的是 CPU）。这一点写进了脚本注释和双语说明，上表因此仍是 CPU 实测。
