### S2 — 发现并修复专用路径开关的缓存键缺陷（影响 CUDA 与 KUPL）
- 现象: 先 `specialize=False` 再切 `True`，性能不回落到专用值
  （CUDA E4：False 1.376 ms → True 1.159 ms，而纯净 True 应为 ~0.68 ms）
- 根因: 原生程序缓存键（`_native_plan_key` / `_contract_signature` /
  `contract_expression` 的 `native_cache` 键）**没有包含"是否禁用融合"状态**，
  导致先前编译的通用程序被复用
- 修复: 引入 `_fused_disabled()`，把该状态并入上述三处缓存键
- 关键输出（修复后，同一进程内反复切换）:
  - CUDA E4: False 1.808 ms → True **0.735 ms** → False 1.611 ms → True **0.746 ms**
  - KUPL E5: False 1266.82 ms → True **112.68 ms** → False 1006.71 ms
  - 四次调用 `out_sum` 完全一致（CUDA 9.410919e+03；KUPL -1.343492e+04）→ 数值未变
- 退出码: 0
- 证据与判断: 切换现在双向生效且数值一致
