   作为唯一数字**；跨运行稳健的结论是「中位 ≈1.6–2.0」。表内逐格数字已取 4 次中位。

四、机制：视图 vs 副本，以及「为什么会挑到要轴置换的那条」
--------------------------------------------------------------------------------

4.1 视图 → `kupl_topology`，副本 → `kupl_dedicated`（补充实验，6 格）
--------------------------------------------------------------------------------
`order` 变体只有 seq 3 带轴置换，为了不让「视图 vs 副本」这个结论只靠 1 格支撑，
补测了 6 条 `axes` 族变体（把某个秩≥2、全轴>1、无重复标签的操作数轴序反转，
张量物理存成变体轴序）。数据在计时区外构造；每格 9 次中位。

| seq | 映射 kind | 非连续操作数 | 视图 ms（route） | 副本 ms（route） | 副本/视图 |
|---:|---|---:|---:|---:|---:|
| 1 | operand-axes | [2] | 0.374（**kupl_topology**） | 0.098（dedicated） | 0.26 |
| 2 | operand-axes | [2] | 0.399（**kupl_topology**） | 0.115（dedicated） | 0.29 |
| 855 | operand-axes | [4] | 0.753（**kupl_topology**） | 0.372（dedicated） | 0.49 |
| 866 | operand-axes | [4] | 0.795（**kupl_topology**） | 0.425（dedicated） | 0.53 |
| 1623 | operand-axes | [5] | 0.881（**kupl_topology**） | 0.385（dedicated） | 0.44 |
| 1863 | operand-axes | [6] | 1.061（**kupl_topology**） | 0.457（dedicated） | 0.43 |

**6/6 视图落 `kupl_topology`、6/6 副本落 `kupl_dedicated`**，副本快 1.9–3.9×。
机制未变：`try_dedicated` 首道门就是 `if any(not operand.flags["C_CONTIGUOUS"])`。
`_equivalence` 的 docstring 已在 `41ff4b75` 补了「视图不连续」提示，方向正确。

**但这份代价在 `order` 族 16 格里只命中 1 格**，因为纯操作数重排的 transpose 是
恒等、不产生不连续视图。旧报告把「视图倒亏」当成整族结论，在重写后的 `order`
族上**不再成立**。

4.2 新发现缺口：`_alignment` 会主动挑「需要轴置换」的写法（256/2589）
--------------------------------------------------------------------------------
seq 3 的变体 `codp,ambn,egfh,ce,mo,bdf,nph->ag` 落在一个 4 条同构条目的桶里：
```
  seq=5    align=(7, 7, 20)   perms=2  order=(1,0,2,3,4,5,6)  aobp,cmdn,egfh,ce,mo,bdf,nph->ag
  seq=3    align=(7, 7, 16)   perms=0  order=(1,0,2,3,4,5,6)  ambn,codp,egfh,ce,mo,bdf,nph->ag   <-- 更优
  seq=6    align=(6, 6, 16)   perms=4  order=(1,2,0,3,4,5,6)  aobp,cgdh,emfn,ce,mo,bdf,nph->ag
  seq=4    align=(6, 6, 14)   perms=2  order=(1,2,0,3,4,5,6)  ambn,cgdh,eofp,ce,mo,bdf,nph->ag
```
两条前两分量**完全相同** `(7,7)`，只差第三分量（共有字母数）20 vs 16，于是 seq=5
优先。但 seq=3 那条给出 **`perms=0`**（纯操作数次序，张量全连续），seq=5 那条要
`(1,0)` 与 `(1,0,2)` 两个轴置换 → 其中一个操作数变非连续 → 视图落 topology。

**实测代价**（seq 3，9 次中位）：
```
映射到 seq5 写法（需轴置换）view : 3.959 ms  kupl_topology
映射到 seq5 写法            copy : 3.508 ms  kupl_dedicated
映射到 seq3 写法（零置换）      : 3.477 ms  kupl_dedicated   <-- 最优但没被选
c3 变体直接算                  : 2.074 ms  generic
```
注意：**即使选对，seq 3 仍然 <1**（3.477 > 2.074），所以这不是 seq 3 翻转的原因，
但它是**净损失**（3.959 vs 3.477，慢 14%）且**可修**。

**全语料规模**（`order` 变体全扫，seq 1..2589）：
```
scanned order-variants: 2589, mapped: 2589
with axis perms: 256
PERM BUT a perm-free alternative exists: 256      # 全部 256 条都可避免
examples: [(3,'operand-order+axes',1), (5,...,1), (39,...,4), (40,...,6), ...]
```
即**所有 256 条带轴置换的映射，桶内都存在零置换替代**（9.9% 的变体因此凭空
拿到不连续视图）。修法很小：`_alignment` 排序键把「置换数量」提到「共有字母数」
之前（或在同 `(same_set, same_text)` 内优先 `perms==0`）。**本次未改代码**（任务
只允许写 logs 一项）。

--------------------------------------------------------------------------------
```

WARM same call median 0.317 ms  min 0.289 max 0.388
```

这是**一次性**成本：之后所有查询走缓存。因此：
* 批量场景（一次进程查很多方程）→ 摊销后 0.5 ms/次，可接受；
