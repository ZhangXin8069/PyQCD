## 一、MPI：`undefined symbol: ompi_mpi_byte`

**根因**（子代理 G 取证 + D 实测）：`make.sh` 只用“是否导出 `applyContractMpiQcd`”判定
MPI 成功，从不检查 `DT_NEEDED`；链接器恒为 `CXX`，而集群环境里 `CXX` 常被固定成 conda g++。
结果编进了 MPI 宏、链接却没带 `libmpi` —— 安装成功，`dlopen` 才失败。

**修复**：判定改为端到端（探针 `--no-undefined` 链接真实 MPI 调用 + `DT_NEEDED` 含
`libmpi*` + `ldd` 可解析）；链接参数按 `PYQCD_EINSUM_MPI_LINK_FLAGS` → CXX wrapper →
`mpicxx --showme:link` → `-lmpi` 阶梯解析并补 rpath；`auto` 无法用 MPI 时降级并说明，
显式 `ENABLE_MPI=1` 直接 `exit 2`；构建后硬校验失败 `exit 3`。

此外运行期加了韧性：`dlopen` 遇到 `undefined symbol` 时先预加载 MPI 运行时再重试一次
（幂等、失败仍 fail-open），报告里会写 `load_retry=preloaded libmpi.so.40`。

## 二、编译期报错可操作化（你的新要求）

统一为四段式，覆盖 gcc/g++、bash、binutils(nm)、OpenBLAS、MPI、nvcc、Cython：

```
error: C++ compiler (g++) is required to build the KUPL native backend.
  missing: C++ compiler (g++)
  needed:  the KUPL backend is C++17 source and cannot be built without it
  fix:     apt install build-essential | dnf install gcc-c++ | conda install -c conda-forge gxx_linux-64
  bypass:  PYQCD_SKIP_NATIVE_BUILD=1 pip install pyqcd (pure-Python planner)
  doc:     https://py-qcd.readthedocs.io/en/latest/install.html
```

编译失败还会按日志补一条 `note:`（`mpi.h` / `omp.h` / `-lopenblas` / MPI 符号未解析）。
OpenBLAS 构建期缺失降为 warning（它其实是运行期 `dlopen`），`-march=native` 增加可移植性提示。
