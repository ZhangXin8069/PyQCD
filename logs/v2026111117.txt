1. `setup.py` 的 KUPL 工具链探测只认 `CXX`/`c++`，而 `cpp/kupl/einsum/make.sh` 实际按

   成功的编译被跳过；
2. KUPL 是原生基线，但构建失败只 `warnings.warn`；pip 成功时不回放构建输出 →
   用户拿到一个不含任何原生库的包，运行时才降级。

## 一、根因（不是版本回归）

三个子代理并行取证，结论一致：

| 检查 | 结果 |
|---|---|
| 0.3.0 / 0.3.1 / 0.3.2 sdist | 成员清单逐行相同（156 文件），`setup.py`/`MANIFEST.in` 零差异，`cpp/` 树哈希相同，均无预编译 `.so` |
| 本机三版安装 | 都能生成 357752 B 的 `libpyqcdeinsum_kupl.so`（SHA256 相同） |
| 受控复现 | `CXX=/bin/false` 装 0.3.2 → pip exit 0、无 `.so`、非 verbose 输出零告警；运行期逐字复现你的警告 |

真正的两处问题（叠加）：

1. **编译器探测误判**：`setup.py` 只查 `CXX`/`c++`，而 `cpp/kupl/einsum/make.sh` 实际是
   `CXX → g++ → c++ → mpicxx`。只装 `g++` 的集群被判成"缺工具链"，本该成功的编译被跳过。
2. **失败静默化**：KUPL 是原生基线，但构建失败只发 `RuntimeWarning`，而 pip 成功时不回放
   构建输出，于是你拿到一个没有任何原生库的包，直到运行时才看到那一条警告。

## 二、修复

- `setup.py`：探测顺序对齐 `make.sh`，KUPL 增加 `nm` 检查；**KUPL 缺库默认中止安装**，
  信息里给原因、`build.log` 路径和两个显式退出开关（`PYQCD_SKIP_NATIVE_BUILD=1` /
  `PYQCD_EINSUM_REQUIRE_NATIVE=0`）；CUDA 仍只警告；源码树已有库时复用。
- 运行期诊断：`library_report()` 区分"库缺失 / 加载失败 / 编译上下文不可用"，
  警告给出绝对路径、`present`、`backend`、`array_backend` 与修复建议，仍 fail-open 且只发一次。
- 新增 4 项原生安装诊断契约（已登记进全量套件）。
- README 双语、双语安装页、`pypi-release` 技能同步新策略，并记录 `g++` 探针这条教训。
