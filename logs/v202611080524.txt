- 证据与判断:
  - 首次 KUPL 构建失败：`mpi_runtime.cpp:7:10: fatal error: mpi.h: No such file or directory`。
    根因是 conda 把 `CXX` 固定为 `x86_64-conda-linux-gnu-c++`，`make.sh` 的 `auto` MPI 探测因
    `mpicxx` 存在而启用 MPI 分支，但该编译器不带 MPI include。改用 `PYQCD_EINSUM_ENABLE_MPI=0`
    构建非 MPI 版本（单机性能与 MPI 无关）；MPI 验证需 `CXX=mpicxx`，留待后续。
  - `make-nv.sh` 默认架构 `6.0 7.0` 且不生成 PTX，在 sm_89（RTX 4060）上不可运行，必须显式
    `PYQCD_CUDA_ARCHITECTURES=8.9`。
  - `make.sh` 打印 `OpenBLAS: not found`（conda 无 `cblas.h`），但 `apply_contract.cpp` 走 dlopen
    运行期绑定 `libopenblas.so.0`（存在），数值路径正常。属探测提示与实际不符，非缺陷。
  - 原 `pyqcd/einsum/cuda/einsum.cpython-310-*.so` 与本机 Python 3.12 不匹配，已重建为 cp312。

### S4 — CPU 基线实测（单机，4 线程，complex128，同 greedy path）
- 命令/操作:
  `PYQCD_EINSUM_ORACLE=installed PYQCD_EINSUM_NATIVE=kupl PYQCD_BENCH_THREADS=4 python -m pyqcd.testing.einsum.bench_native --data synthetic --profiles T0|T1 --backends cpu --iters 10 --warmup 2`
- 关键输出（median/s，opt vs qcd，speedup，max rel err）:
  - T0 (Nvec=20, spatial=1): E1 0.029578 / 0.057578 / 0.514x / 2.7e-14；
    E2 0.072729 / 0.056375 / 1.290x / 2.6e-15；E4 0.000708 / 0.000535 / 1.323x / 3.3e-14；
    E5 0.000191 / 0.000201 / 0.953x / 0.0
  - T1 (Nvec=100, spatial=1): E1 4.266694929 / 1.546226513 / 2.759x / 1.23e-14；
    E2 21.84825881 / 0.564247697 / 38.721x / 9.13e-15；E4 0.007397338 / 0.004068588 / 1.818x / 1.69e-13；
    E5 0.000112043 / 0.000112081 / 0.9997x / 0.0
- 退出码: 0（`bench_native` 因 <3x 判 FAIL，符合其门禁语义）
- 证据与判断:
  - E2 的 38.7x 不是“我们快”，而是 opt_einsum 在该 path 未走 BLAS，单次 2.18 s；报告中必须同时给绝对耗时。

  - T0/E1 仅 0.51x，说明小张量下我们的单次调用固定开销压过计算。
  - 注意：必须经 `bench_native` 启动，否则 `pyqcd.testing` 包初始化会先导入 NumPy，线程钉扎失效
    （首次用 `-m pyqcd.testing.einsum.bench_distillation` 即触发该阻断项）。
  - 产物：`pyqcd/testing/einsum/artifacts/bench_20261108050730`（T0）、`bench_20261108051452`（T1）。
