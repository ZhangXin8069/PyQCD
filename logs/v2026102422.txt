--- report begin ---
**结论**

按整库或“核子中的胶子 TMD-PDF 全链”判据，**不等价**。更准确地说：

- `refer/donghx` 当前归档实现的是**核子外态、断连、直线 Wilson line 的胶子准 PDF / LaMET 诊断链**，不是横向 TMD。
- PyQCD **移植/重实现了其中若干底层模块**，并另外增加 `b_perp` 与三段 staple，形成胶子 TMD 矩阵元诊断原型。
- 两边都**没有**完成可用于物理发布的核子胶子 TMD-PDF；因此也不能用“底层公式相同”推出“全链等价”。

**分段判定**

| 物理层 | PyQCD | refer/donghx | 判定 |
|---|---|---|---|
| 4D Wilson flow、Clover、对偶场强 | RK3 与四叶 Clover 在 `_gradient_flow.py`、`_gluon_ope.py` 实现 | `flowed_gluon_ope.cpp` 使用相同流方程/场强定义 | 算法等价；非逐位同码 |
| 直线胶子 OPE | `schema-v2` Python 重实现，见 `_gradient_flow_gluon_ope.py` | C++ `compute_ope` 输出相同六轴 schema | 受控输入下数值等价 |
| GF→MS-bar 端点转换 | `_gradient_flow_quasi.match_one` | `gluon_flow_to_quasi.match_one` | 显式移植；legacy policy 下输出逐位相同 |
| 断连 C3 真空扣除 | `_gradient_flow_ratio.py` 与主 TMD `_disconnected.py` | `calc_ratio_matched.py`、`construct_bootstrap.py` | C3 代数相同；统计/分母约定不完全相同 |
| 核子两/三点 | 有源分辨蒸馏 C2，并用 `C2·Lg` 因子化得到断连 C3 | C++ 只产胶子 loop，C2 从外部产物读入 | 都是断连近似，不是直接全 Wick 胶子 3pt |
| 横向 TMD 算符 | 有 `b_perp`、staple、`M^{ti;ti}+M^{tj;tj}-2M^{ij;ij}` | 当前源码未发现 `b_perp`/横向 staple，只有沿 z 的直线链接 | **不等价：PyQCD 扩展，donghx 无对应全链** |
| Z_R、soft/rapidity、TMD matching | Z_R/hybrid API 存在但活动链未用；soft=1、CS 为两动量 proxy、gg-only | 有端点转换、flow-time 外推和 gg-only LaMET；无 TMD soft/CS | 仅有部分公式亲缘，不能互称等价 |
| 连续极限 | 有外推接口，活动链明确未做 | 单格距、未做连续极限 | 双方均未闭合 |

**关键证据**

1. PyQCD 的直线 OPE 文件明确写着“参考 schema-v2 梯度流胶子 OPE”，并在 `_straight_bilocal`、`_component_set` 中复现 donghx 的 `+z/-z`、双场强和 `T±S` 组合。用 donghx 自带独立 float64 oracle 交叉检查，unpolarized 最大误差 `8.897e-16`，helicity 最大误差 `2.231e-16`。这说明**这一层确实可视为等价移植**。

2. donghx 的 C++ 元数据将 `nucleon_C2C3`、`vacuum_subtraction`、`renormalization`、`flow_to_MS_matching`、`LaMET_matching` 列为 `not_applied`；其技术说明也把空间分离固定为 `z_mu=(0,0,z,0)`。因此归档中的“胶子 PDF”主线是共线准 PDF，不是 `b_perp` TMD。

3. PyQCD 的 `_tmd.py` 才显式实现 `b_perp` 与三段 staple，并有 `tmd_matrix_elements_time` 输出 `(nz,nb,Nt)`；这是 donghx 当前快照没有的 TMD 几何扩展。其几何/规范不变性合同测试通过，但这只证明算符代数与几何，不证明完整 TMD 方案。

4. PyQCD 的主工作流自己也标记为 `diagnostic_only`、`physical_acceptance=False`，并列出 `soft_rapidity_not_measured`、`single_fixed_flow_time_no_tau_extrapolation`、`single_lattice_spacing_no_continuum_limit`、`fixed_staple_length_no_ell_extrapolation`、`gg_only_no_gluon_quark_mixing` 等未闭合项。

5. `schema-v2` ratio 也不是完全同码：donghx 规定并用 `Re(C2_nopol)` 作分母；PyQCD `_gradient_flow_ratio.py` 保留复 C2 除法。受控复输入下 central C3 完全一致，但 ratio 因分母约定可差 `6.770e-3`。PyQCD 主 TMD 的 `_disconnected.ensemble_covariance_ratio` 又改回用 `Re(C2)`，所以不存在一条贯穿两库的完全同一统计实现。

6. 有两类容易误判的名词：donghx 的 `M_boot`、`b` 多数是 bootstrap/内部指标，不是 `b_perp`；donghx 的 `staple` 是 Wilson-flow 六链接 staple，不是 TMD 横向 Wilson-line staple。

**验证**

当前工作树已运行相关合同测试：十个有显式计数的 PyQCD 套件 `115/115` 通过，另两个 TMD 合同模块退出码为 0；donghx 的 `flow_to_quasi` 测试 `2/2` 通过；`pdf_workflow --dry-run --smoke` 通过。受控交叉验证显示：flow-to-quasi 与 gg 匹配核在对应策略下逐位一致；同 `hbar` 下 Fourier 积分器一致，但两库默认 `hbar` 常数不同。未在相同真实系综上运行完整端到端对照，因此结论是“源码与受控数值层面的等价边界”，不是“全链真实数据输出等价”。

**判断口诀**

- 若问题是“PyQCD 的直线 `schema-v2` 胶子 OPE 是否移植自/等价于 donghx？”：**大体是，核心公式和受控输出可视为等价**。
- 若问题是“PyQCD 的核子胶子 TMD-PDF 全链是否等价于 donghx？”：**不是；donghx 当前实现是直线准 PDF 诊断链，PyQCD 是在其基础上新增 staple TMD 的诊断原型**。
