--- report begin ---
已按指令去掉 KUPL 拓扑入口的兜底，两侧语义统一为"查不到步表 = status 4"。

**旧表 CPU 的 dedicated 与 topology 差 89 ms 的原因**：那不是两条步表路径的差异，而是 `topology` 当时根本没进步表——scene 是异形轴，`run_specialized` 第一关就卡在 `uniform_dimension()`（步表要求所有轴长等于同一 `dim`），于是走了兜底 `execute_parsed_contract`，也就是 generic 用的同一个原生执行器，只省掉 Python 逐步 dispatch（120.00 → 97.61 ms）。而 `dedicated` 真跑了步表，每步都要 pack/unpack，seq=129 的 `plan_pack_bytes` 是 524.6 MiB，那 89 ms 全部是打包成本。旁证：轻路径 seq=1623（pack 仅 29.2 MiB）两者接近（5.03 vs 5.35 ms）。

**改动**：`apply_topology` 末尾不再兜底，直接返回 UNSUPPORTED。

**连带必须修的两处**（否则死锁）：① 探测方程 `ij,jk->ik` 不在语料步表里，之前靠兜底才"通过"，去兜底后探测恒失败→dtype 永不启用→连语料方程也被拦住；改为语料第一条 `cadb,menf,ac,em,bd,fn->`。② 探测容差统一 1e-9 会把正确的 complex64 判错（实测 rel=3.6e-7），改为按精度分档。

**契约连带约束**：验"真的下发成功"的用例，方程必须来自基础表前 2582 条（步表真实边界），附录 2583+ 一律 status 4；相关三处契约已改写。

**结果**：基表抽样 44/44 命中、0 失配；跨附录 26/88；全量 **124 passed / 1 skipped / 0 failed**。KUPL scene 表的 `topology` 列现在全部 MISS（诚实反映"异形轴不在步表覆盖内"），`dedicated` 数据不变。
