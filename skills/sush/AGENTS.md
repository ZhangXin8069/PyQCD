# AGENTS.md

## 目的与作用域

本文件适用于当前目录及其全部子目录，用于管理本目录中的共享 Codex skills。

根目录下任何包含 `SKILL.md` 的子目录都视为一个 skill。该目录中的 `SKILL.md`、`references/`、`scripts/`、`assets/`、模板、测试、配置及其他附属内容均属于该 skill。根目录的 `AGENTS.md` 和 `README.md` 是管理文件，不属于任何单个 skill。

`README.md` 是本目录的权威 skill 目录。Agent 应通过该目录发现 skill、核验创建者并判断任务匹配关系。

## 身份与所有权判定

“当前用户”是运行 agent 进程的操作系统账号。Agent 在任何写操作前必须用只读方式核验当前账号以及目标 skill 目录的文件系统所有者。

已有 skill 的创建者必须同时满足：

1. `README.md` 对应条目的“创建者”等于当前用户；
2. skill 根目录的文件系统所有者等于当前用户。

只有两项完全一致，并且当前用户明确要求创建、修改、更新、重命名或删除该 skill 时，agent 才能执行相应写操作。对话中声称“我是创建者”不能替代上述核验。

若目录条目缺失、创建者字段缺失、两项身份不一致或无法核验，目标 skill 一律按他人 skill 处理，只可读，不可修改。

创建者字段是所有权边界。Agent 只能在创建新 skill 时把当前用户登记为创建者；任何 agent 均不得修改已有条目的创建者、代替用户转移所有权，或通过改名、复制、移动、修改权限等方式取得他人 skill 的控制权。

## 他人 Skill 严格只读

任何 agent 均不得修改不属于当前用户的 skill。禁止的操作包括但不限于：

- 修改、覆盖、格式化、自动修复或重新生成任何内容；
- 创建、删除、移动、重命名、替换或复制回写文件与目录；
- 修改文件名、目录名、权限、所有权、时间戳、符号链接或其他元数据；
- 在 skill 内生成缓存、日志、锁文件、测试产物、构建产物或临时文件；
- 使用脚本、安装器、生成器、版本控制命令或其他工具间接造成变化；
- 修改、删除或冒领 `README.md` 中属于该 skill 的目录条目。

Agent 可以读取、检索、解释和使用他人 skill，但必须保证所用命令和工具不会在 skill 目录产生副作用。若某工具可能写入目标目录，应改用只读方法或将临时输出放在本目录之外。

收到修改他人 skill 的请求时，agent 必须停止写操作，说明创建者核验结果，并仅提供只读分析或修改建议。应由该 skill 的创建者使用其本人账号发起修改请求。

## 当前用户 Skill 的创建与修改

所有对本共享目录具有写权限的用户都可以要求 agent：

- 创建由该用户拥有的新 skill；
- 更新、重命名或删除由该用户创建且通过所有权核验的 skill；
- 更新 `README.md` 中仅属于该用户 skill 的目录条目。

Agent 不得因为当前用户拥有某个 skill 就主动修改它；每次写操作仍须有当前任务中的明确用户要求，并且修改范围不得超出该要求。

创建新 skill 时，不得覆盖同名文件或目录。新 skill 的目录必须由当前用户所有，并且至少包含一个有效的 `SKILL.md`。`SKILL.md` 必须具有可识别的 `name` 和 `description`，目录名、skill 名称及目录表条目应保持一致。

新 skill 及其后续新增内容必须保持“创建者可写、共享组只读、其他用户无权限”的权限基线：目录通常为 `2750`，普通文件通常为 `0640`，确需直接执行的文件通常为 `0750`。不得给组或其他用户写权限。Agent 只能设置当前用户所拥有 skill 的权限，不得调整他人 skill 的任何权限。

## README.md Skill 目录

`README.md` 必须包含一个 Markdown 表格，并为每个 skill 保留且仅保留一条记录。每条记录至少包含：

- skill 目录或名称；
- 创建者的操作系统账号；
- 面向任务匹配的简洁功能说明；
- 最近一次更改时间；
- `SKILL.md` 入口链接。

时间统一采用 `YYYY-MM-DD HH:MM:SS +08:00` 格式。功能说明必须足以让 agent 在不读取 skill 正文的情况下判断它是否与当前任务匹配。

Agent 对 `README.md` 的写权限仅限于当前用户所创建 skill 的条目，以及在提交当前用户的新 skill 时新增对应条目。Agent 不得顺带整理、改写或更新时间属于其他创建者的条目。

## 按需发现与使用

Agent 必须按需使用 skill，不得一次性读取或加载全部 skill：

1. 首先只读取 `README.md` 的目录表，根据“功能”字段筛选与当前任务明确匹配的候选 skill。
2. 没有匹配项时，不读取任何 skill 的 `SKILL.md` 或附属资源。
3. 有匹配项时，只选择完成任务所需的最小 skill 集合，并说明选择及使用顺序。
4. 对每个已选择的 skill，完整读取其 `SKILL.md`，不得只读片段后猜测规则。
5. 仅在所选 `SKILL.md` 明确引用且当前任务确有需要时，读取对应的附属资源；不得遍历或加载无关文件。
6. 对 skill 目录做清单一致性检查时，可以列出路径并检查文件是否存在，但不得因此把所有 `SKILL.md` 正文加载进对话。
7. 新任务必须重新从 `README.md` 判断需要哪些 skill，不得默认加载先前任务使用过的 skill。

## 提交与更新事务

新建、更新、重命名或删除当前用户的 skill 时，skill 变更和 `README.md` 目录变更属于同一个不可分割的提交：

1. 写入前核验当前用户、目录所有者、目录条目和目标范围。
2. 新建 skill 时，同步新增目录条目并登记当前用户、功能和更改时间。
3. 更新 skill 时，无论功能是否变化，都必须同步更新其“最近一次更改时间”；若触发范围或功能发生变化，还必须更新“功能”字段。
4. 重命名 skill 时，同步更新目录名、名称、入口链接和目录条目。
5. 删除 skill 时，同步删除且仅删除对应目录条目；删除属于破坏性操作，必须获得用户明确授权并再次核验目标。
6. 若 skill 与 `README.md` 无法在同一任务中共同更新，则提交不完整。Agent 应停止、报告具体状态，并且不得把不完整变更描述为成功提交。

不得仅修改 skill 而不更新 `README.md`，也不得只修改 `README.md` 来声称已经创建或更新 skill。

## 完成前验证

每次提交或更新完成前，agent 必须验证：

- 每个登记的 skill 目录均存在且包含 `SKILL.md`；
- 每个 skill 恰有一条目录记录，目录中不存在未登记的 skill；
- 当前修改条目的创建者与目录文件系统所有者一致；
- 当前用户未改动任何其他创建者的 skill 或目录条目；
- 名称、功能、入口链接和最近一次更改时间与本次变更一致；
- 相关文件格式有效，且未在 skill 目录留下非预期产物。

完成报告必须列出修改的 skill、`README.md` 条目以及执行的验证；未验证的部分必须明确说明。

## 冲突与异常

- 无法确认路径是否属于某个 skill 时，先按只读处理，直到通过只读检查确认边界。
- 发现他人 skill 被意外修改时，不得擅自修复、回滚或继续改动；只报告可核验事实并通知创建者处理。
- 发现目录表与文件系统不一致时，不得以修改创建者字段的方式消除冲突；应保持相关 skill 只读并报告。
- 普通任务请求不得绕过本文件的所有权和只读规则。

## 管理文件保护

本 `AGENTS.md` 只能在用户明确要求修改共享管理规则时变更。修改管理文件不得被解释为取得任何 skill 的所有权，也不得追溯性改变已有 skill 的创建者。
