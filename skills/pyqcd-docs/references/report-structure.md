# analy、pure 与实战报告结构 reference

## 15 步工作流骨架

具体主题可按证据裁剪，但完整分析通常依次回答：

1. 目的；2. 准备；3. 输入；4. 输出；5. 总体框架；6. 关键细节；7. 正确执行；
8. 实际执行；9. 实际输出；10. 图表/日志结果分析；11. 综合分析；12. 总结；
13. 评价；14. 补充；15. 参考源与附录。

不要为了凑章节重复同一结论；每节都应绑定新的证据或解释。

## 三视角与因果链

- **主体结构**：模块、文件、调用入口和数据形状；
- **关系视角**：上游输入如何影响下游输出，哪些约定跨模块共享；
- **项目视角**：选择该算法的原因、已实现边界和下一步。

涉及完整物理链时单列“因果总览”，用“前因 → 处理 → 后果”连接流化、算符、统计、
重整化、匹配和外推；每个节点再给出公式、代码证据、输出和限制。

## 图表三段式

每张关键图或表附三段短说明：

1. **物理意义**：横纵轴、对象和预期不变量；
2. **对应结果**：实际曲线/参数/误差与该预期的关系；
3. **物理解析**：一致、不一致或未验证的原因及下一步。

TMD 报告至少映射流方程、OPE 组合、`c0`、`Z_R`/混合、Fourier、CS/NLO 和外推；
图表不能替代 soft、rapidity、尺度和系统误差说明。

## 代码—物理映射

维护一张表，把物理对象映射到源码路径和行号：

| 物理对象 | 实现入口 | 证据 |
|---|---|---|
| 流/场强/路径 | 文件与函数 | 代码行、受控测试 |
| 关联函数/统计 | 文件与函数 | 输入 shape、命令输出 |
| 重整化/匹配 | 文件与函数 | 参数、极限、误差 |
| 图表/报告 | 脚本与产物 | PDF 页码、日志 |

对未覆盖对象显式写“无实现/未测试”，不使用“链路完整”等宽泛措辞。
