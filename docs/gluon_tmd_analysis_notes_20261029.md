## 2. 分析层经验

### 2.1 复数比值

- 已发布 `unpolarized_ratio` 是复数。任何与实数数组的比较都必须先取实部；
  本轮第一次交叉检查因为漏取实部，得到 `0.43/0.92/16.4` 的最大假差，
  取实部后降为 `2.1e-14`。
- 缓存 OPE 的虚部严格为零，`Im(R)` 来自分母 C2 的相位（分子是 OPE 与 C2 的
  协方差估计量）。它既不是信号，也不是误差。
- 分母 `complex` 与 `real` 两种约定要显式声明；跨约定比较必须同时给出模式。

### 2.2 流窗有效性

- 判据是 `sqrt(8τ) < |z|, |b|`。τ/a²=3 的半径是 4.90a，所有 `b≥1` 都在窗外；
  τ=2 的半径是 4.00a，窗内没有任何格点；τ=1 的半径是 2.83a，只有 `b=3,4` 回到窗内。
- 窗内无格点时，判定必须是「不可判定」。本轮曾因默认分支把 τ=2 误标为
  「存在显著流时依赖」。
- 检验功效只能在窗内格点上计算；用全体格点会混入已知越界的 `b`。
- 在 `b≤4` 的网格上**只有 τ=1 存在窗内格点**（`b=3,4`），任何「流时外推」都无法
  进行。这不是分析脚本能修的，只能扩横向距离。
- 2026-10-29 把 `b` 扩到 6 之后，判据给出三个流时的窗内集合：
  τ=1 为 `b=3..6, z=3..12`（40 点），τ=2 与 τ=3 均为 `b=5,6, z=5..12`（16 点）。
  因此**共同窗**是 `(z≥5, b=5,6)`，共 **16 个** `(z,b)`——这是唯一能同时比较
  三个流时的几何。跨流时结论必须限定在这 16 个点上；不能拿 τ=1 的 40 点
  与 τ=2,3 的 16 点直接比较（那样混入的 `b=3,4` 只在 τ=1 有效）。
- 共同窗只有 16 个 `(z,b)`、每个 `(z,b)` 6 个 `tsep` 窗口均值，仍是小样本；
  任何「流时依赖」的判语都要先看功效再谈显著性。若 `σ` 中位数小于 1，
  正确结论是「无判别力」，不是「一致」。
- 与流半径最接近的 4 个点 `(5,5),(5,6),(6,5),(6,6)` 是窗内**最脆弱**的子集
  （`|z|/r` 或 `|b|/r` 最小）。把 16 点与这 4 点的子集结果分开报告，
  可以区分「流窗边缘效应」与「整体趋势」。
- 共同窗内只有 `b=5,6` 两个横距值，**窗内的有限 b 外推仍然无法进行**；
  16 点全在 `z=5..12` 上变化，自由度主要来自 z。任何「b 依赖已控制」的说法
  都把 2 个 b 值当成了外推区间，属于过度解读。

### 2.3 配对与功效
- 跨流时比较必须对**差值**做配对 delete-one JK；分别求误差再相加会重复计入共模噪声。
- `σ` 小不等于差值为零。必须同时报告中位 `|ΔR|/|R_ref|`；该比值大于 0.5 而
  `σ<1` 时，正确判语是「无判别力」，不是「一致」。

### 2.4 共同流窗内的流时依赖（本轮阳性结果）

`b` 扩到 6 之后，共同窗 $(z\ge5,\ b=5,6)$ 让流时比较第一次有了窗内格点。
两个独立估计量给出同一图案：

| 估计量 | $\tau=1$ vs 2 | $\tau=1$ vs 3 | $\tau=2$ vs 3 |
|---|---|---|---|
| 比值层（96 格点，中位 $\sigma$） | 0.91 / 0.59 / 0.66 | 0.45 / 0.57 / 0.42 | **1.34 / 1.62 / 0.87** |
| 比值层（中位 $|\Delta R|/|R|$） | 1.66 / 0.86 / 0.97 | 2.35 / 1.26 / 1.67 | 1.41 / 1.30 / 1.27 |
| C3 层（$P_{200}$，插入 1，16 点） | 0.52，2/16 为正 | 0.98，1/16 为正 | **2.59，0/16 为正（全负）** |

（比值层每格是 P000/P200/P400 三个动量；C3 层数字是平均 $|\sigma|$ 与正号点数。）

- **$\tau=2\to3$ 是系统性的。** $P_{200}$ 的 16 个 $(z,b)$ 在三个插入时间上
  $\Delta=P(2)-P(3)<0$ **全部同号**，中位 $-1.2\sim-1.6\times10^{-3}$；
  $P_{000}$ 在插入 3、5 上同样 16/16 为负。同号的点高度相关，不能当 16 次
  独立检验，但「全部同号 + 中位 $2\sigma$ 级」不是独立噪声能产生的。
- **配对误差是判定成立的前提。** 同一组数用「两个误差平方相加」只有中位
  $0.95\sigma$，配对后 $2.57\sigma$：共模噪声在差值里相消，平方和把它算了两次。
  这就是 §2.3 那条规则的量化版本。
- **边缘 4 点同向**（$P_{200}$ 的 $\tau=2\to3$：12/12 同号，$1.0$--$3.4\sigma$），
  所以这不是流窗边缘的伪影。
- **$\tau=1$ 与 $\tau=2/3$ 没有一致显著差异**：$P_{200}$ 上 0 个点 $|\sigma|\ge2$；
  $P_{000}$ 的 $\tau=1\to2$ 反而 16/16 同号，但只有 $0.75\sigma$。
  方向随动量/插入时间改变，属于「有结构但未达判定」，不要写成趋势。
- 因此正确的表述是「在共同窗内检测到流时依赖，$\tau=3$ 的 $P$ 高于 $\tau=2$」，
  **不是**「流时无关」；也不能把三个流时串成一条单调曲线。
- 仍不能上升为物理结论：窗内只有两个 $b$ 值；$\tau=3$ 的流半径 $4.90a$ 与
  $b=5a$ 只差 $0.1a$；9 组态、delete-one 秩 $\le8$；无 $\tau\to0$ 外推。

## 3. 统计层经验

- 9 个组态的 delete-one JK 给出 9 个复制品，协方差秩上限为 8。任何需要多于
  8 个独立方向的联合拟合都会撞到这个硬上限。
- 两态联合拟合在数值上完全可行：质量分裂 12/12、χ²/dof 12/12、窗口内
  B00 稳定 12/12，但 `|B00|/σ≥2` 只有 0/12。**「模型能描述数据」与
  「数据约束了参数」是两件事。**
- B00 的误差远大于比值误差：B00 用的是 C3 绝对量，而比值让分子分母共享的
  组态涨落部分相消。
- `χ²/dof<1` 只表示「没有看到张力」，在强相关的 9 组态数据上不构成模型验证。
- **相关参数会互相交换显著性。** τ=1、tsep=5…24 下 `B00`（4.5σ）与
  `B01`（`left0*right1` 列）同时显著且反相关；物理量是
  `P(τ)=B00+B01·e^{−dm·τ}`，相关组合给出 `P(1)=0.11σ`——单参数显著性被抵消。
  报单参数 `B00` 的显著性等于报一个可被另一参数抵消的组合。
  同一拟合的 `P(3)=4.6σ`、`P(5)=4.5σ` 说明信号在更晚的插入点，
  而那些 τ 在 `b≤4` 上全部出流窗。
- **低 `χ²/dof` 完全掩盖退化。** C2 单独两态拟合在 `t=5…16` 给出
  `A1/A0=−1.2e5`（两指数近共线），`χ²/dof` 却只有 0.63。判据是振幅比量级，
  不是拟合优度。
- **窗口不是越多越好。** `[16,24]` 上 `B00` 误差涨到 `1e-1`，参数被尾部噪声推动；
  此前把 `[11,16]` 的偏移读成「`B00` 随窗口单调漂移」是错误归因——加入 `[5,24]`
  后 `B00` 与 `[5,16]` 仅差 1%，漂移来自后期窗口退化而非系统趋势。

## 4. 计算工程经验

### 4.1 零成本区间扩展

full-channel OPE 缓存的插入轴覆盖整条时间序列（72 点），C2 也按整条序列加载，
因此把 `tsep` 从 5…10 扩到 5…16 只需改分析脚本的 `tseps` 参数：不流化、
不重算 OPE、不写缓存。扩展后旧区间必须与已发布产品逐位一致（本轮
`5.6e-17` / `5.6e-17` / `8.9e-16`）。

扩展的合法性还需要单独证明：把 `max_tsep` 从 10 改到 16 后，重叠的
`(tsep, insertion)` 的 C3 必须逐位相同。本轮 3315 个格点的最大差为 `0.0`，
有限性掩码完全相同（`c3_grid_invariance.json`）。

复现检查只能改一个变量。本轮第一次做 `[5,10]` 子窗口复现时把 C2 拟合区间也扩到了
16，得到 `|ΔB00|=3.2e-3` 的假差异；修掉上界、只写 `c2_t <= 10` 后仍有 `5.2e-3`，
因为已发布模块的区间是 `C2_TMIN=1`，缺下界就把 `t=0` 带进了拟合。按
`(c2_t >= 1) & (c2_t <= 10)` 取掩码后复现差降为 **0.0**（P000/P200 均是）。
教训是复现检查不要重写区间，直接复用已发布模块的 `C2_TMIN/C2_TMAX`。
主拟合固定 C2 区间，另设一个 C2 区间敏感性变体，把「新增 C3 数据点」与
「C2 模型变化」分开。

### 4.2 缓存隔离

流时缓存的 contract 键包含 `tau` 与 `flow_contract_sha256`，τ=1、2、3 并存
互不覆盖。扩展前先确认 key 的组成，避免误以为会覆盖参考流时产物。

### 4.3 复用已发布拟合

扩展 tsep 时不要复制一份拟合代码。用
`importlib.util.spec_from_file_location` 按路径导入已发布脚本，只替换模块级
`TSEPS`，再把旧窗口结果与已发布 JSON 逐位比对。复制代码会引入第二套符号约定。

### 4.4 数组轴先验证再写循环

本轮两次轴错误都来自按名字猜轴：`sigma` 是 `[z][b][tsep]`，比值的样本轴在最后。
写循环前先打印 shape 和一个切片，是成本最低的防线。

### 4.5 生成式文档不能硬编码窗口与区间

加入 `--tsep-max` 之后，脚本里残留了 6 处硬编码：标题「扩展（5…16）」、
「替换为 5…16」、「tsep=5…16」、说明「`[11,16]` 只剩激发态」、
表头「5…16」、provenance note。跑 `tsep=24` 时它们全部变成与结果不符的
陈述，而且**不会报错**——生成的文件看起来完整，只是内容错了。
正确做法是所有区间、窗口标签、数据点计数都从 `results` 派生；
参数化之后必须对生成文件做一次反向检查（`grep 5…16/11,16/8,16`），
并确认 provenance note 与实际运行一致。已发布的 JSON 若已写错，
用同一套 `render()` 从 JSON 重新生成，而不是手改 Markdown。

### 4.6 「自动挑一个拟合」必须先验证挑选规则

把插入时间外推进到 `b=5,6` 时，需要与 `(z,b)` 无关的参考质量 `m0`，
于是从 `c2_only` 里取拟合结果。第一版按字典序取最后一个窗口
（`sorted(keys)[-1]` → `5..16`），P200 得到 `m0=0.0601`，而其余窗口是
0.78--0.80、联合拟合是 0.7912--0.7937：这个窗口的两态拟合退化了，但
JSON 里没有 `converged=false` 标记，`B00_eff` 被 `exp(-m0 tsep)` 放大后
掉到 `1e-7` 量级。规则改为：**显式指定窗口**（优先沿用主拟合的
`t=1..10`），并检查 `m0 ∈ (0.2,1.5)`、与其余可用窗口中位数相差不超过
20%，不满足直接报错。

同理，扩 `b` 时还要同步已发布模块的模块级 `B_LIST`：`_c3_for` 用它决定
C3 的 `b` 轴长度，只改本地全局会让 `_flatten_c3(z,5)` 越界。

### 4.7 GPU 设备映射与后端能力

`nvidia-smi` 的物理索引与 CUDA runtime 索引在本机不一致（V100 是 runtime
的 device 0，`nvidia-smi` 的 index 2）。按 `nvidia-smi` 填
`CUDA_VISIBLE_DEVICES` 会拿到 P100，PyTorch 2.10 只编译 sm_70+，立刻报
`no kernel image is available`。任何 GPU 作业先把「runtime 索引→设备名」
打进日志；CuPy 14 仍带 sm_60 内核，可用于 P100，但必须用与生产缓存逐元素
比较来验证（见 §5）。

混合后端生产的三条规则：

1. **一个后端算一份回归基准。** 若某条判据要求「逐位」，就把那部分任务固定在
   同一后端（本轮 τ=3 全部 9 个组态留在 V100/torch）。
2. **判据随后端分级，而且标签必须与实测值一致。** 原始代码只认「`max|Δ| ≤ 1e-12`」，把 CuPy 的
   `1e-6` 级差异当成失败。现在按该 (τ,conf) 的后端集合判定：
   - 全部 `torch` 且 `max|Δ| = 0.0` → `bit_exact`（这是唯一的 `bit_exact` 用法）；
   - 全部 `torch` 但差 `1e-14` 量级（BLAS 归约顺序）→ `same_backend_1e-12`；
   - 含 CuPy → `float32_equivalent`（相对 Frobenius ≤1e-5）。

   2026-10-29 收尾检查发现比值层 τ=3（全 torch）的 `max|ΔR|` 是 `2.1e-14` 却被标成
   `bit_exact`——数值上无碍（远低于 1e-12），但标签与「bit_exact 只用于 0」的约定冲突。
   同一轮里 OPE 缓存层的 15 个 torch 单元格确实全是 `0.0`，那才是真正的 `bit_exact`。
   把 `criteria`/`tolerance`/`exactly_equal`/`backends` 一起写进产物 JSON，而不是只写在日志里。
3. **后端归属按 (τ, conf) 记录。** 汇总脚本从各 worker 的完成 JSON 重建
   `backend_map`，这样任何一个比值都能追溯到它是哪个后端算的。

单卡多进程在同卡上不划算（实测三进程使单任务从 207 s 退化到约 670 s），
并发度应当等于设备数；多卡按实测速度静态分配，不按卡数均分。

### 4.8 需要重算的批次轴扩展（b 轴）

§4.1 的「零成本扩展」只适用于**分析层**参数（`tsep`）。**几何轴 `b` 不是零成本的**：
full-channel OPE 的 contract 键含完整有序 `b_list`，扩 `b` 必须重新流化并重算。

- **先确认缓存键。** 打开已有缓存读 `pyqcd_cache_contract_json`，确认 `b_list`
  在键里；再对照文件名（本轮 `..._b5_0to4_tau3_...` 与新的
  `..._b7_0to6_tau3_...`），确认新旧并存、不会覆盖。
- **用「旧切片逐位一致」作正确性证据，不要用「独立重算」。** 独立重算既没有独立
  参考（同一份代码），又贵一个量级（24³×72 的 Wilson flow 在单线程 numpy 上要
  几十分钟）。正确做法是拿磁盘上已发布的 torch 生产缓存当参考，比较新缓存的
  重叠切片：本轮 9 个已完成缓存里，torch 算的 τ=3 全部 `max|Δ| = 0.000e+00`、
  NaN 掩码相同；CuPy 算的 τ=1,2 为 `6e-4 ~ 1.9e-3`（`|ref|≈0` 处的绝对差），
  有限性模式完全相同。若不要求「逐位」，必须把这条差异按 `float32_equivalent`
  显式记录（见 §4.7）。
- **新格点要单独验健全性，不能只看「跑完了」。** 检查 b=5,6 是否 100% 有限、
  中位量级是否延续 b=3,4 的趋势。本轮定义「量级」为：先在**单个组态**的
  channel×component×z×t 全部有限元素上取 `|OPE|` 中位数，再对 **9 个组态**
  取中位数（27/27 全部到位后重算）。结果是 τ=3 的 b=3→6 为
  `2.405/1.779/1.566/1.493`，τ=1 为 `3.315/3.107/2.971/2.872`，
  τ=2 为 `2.628/2.104/1.974/1.898`：三个流时都单调衰减、无跳变，
  说明新格点处在同一标度区，不是边界伪影；组态间离散只有 ±4% 左右。
  **引用这类数字时必须同时写出统计口径**（哪些轴、先逐组态还是全部合并、
  中位数还是均值），否则换一个口径就会得到差 5%–10% 的另一组数，
  而两边看起来都「对」。上一版 τ=2 的 `2.66/2.14/2.01/1.91` 只用了 4 个
  已完成的组态，补齐 9 个后应改为上表数值。
- **扩轴后所有下游模块都要同步轴长。** 已发布拟合模块的 `B_LIST` 是模块级常量
  （固定 0..4），只改脚本自己的全局会让 `_c3_for` 只构造 b≤4 的轴、
  `_flatten_c3(z,5)` 直接越界。更稳的做法是**以缓存自带的 `b_list` 为准**
  （`stored["b_list"]`），不覆盖请求的 b 时直接报错；缓存里同时存
  `flow_tau`，下游用它核对「这份缓存是不是这个流时的」。
- **新缓存不要覆盖旧缓存。** 用带后缀的名字（本轮 `c3_cache_tau{T}_tsep24_b7.npz`），
  保证已发布数字仍可按原命令逐位复现。
- **容差要按量级校准，不能拍一个绝对数。** OPE 缓存跨 1e4 量级，float32 的
  ~1e-7 相对舍入在 1e4 上就是 `1e-3` 的绝对差；用绝对容差 `1e-5` 会把正常舍入
  判成失败，用 `1e-2` 又会放过真实错误。判据改为相对 Frobenius 范数
  `||Δ||/||ref||`：本轮 9 个 CuPy 组态实测 `4.8e-7 ~ 7.0e-7`（complex64 地板），
  阈值取 `1e-5`（14 倍余量，仍比任何索引/几何错误低 5 个数量级）。阈值与实测
  范围都要写进产物，否则后来的人无法判断这条判据是否还有意义。
- **通配符要钉住 schema。** 同一目录同时存在 `tmd_ope_v1_*`、`tmd_ope_v2_full_*`
  和 2D staircase 的同 `tau` 缓存；用 `*b5_0to4_tau1_*` 去配对会随机命中 v1，
  得到 `max|Δ| = 1.9e3` 的假失败。检查器必须写全
  `tmd_ope_v2_full_*_b5_0to4_tau{τ}_*`。
- **把抽查固化成脚本。** 生产中途每个组态完成后都要做一次契约+回归+健全性检查；
  用一次性 heredoc 做这件事，判据会随人漂移。本轮把它固化成
  `verify_caches.py`（覆盖/契约/回归/逐 b 统计/后端归属一次输出），收尾检查与
  中途抽查共用同一份判据。
- **复现性抽查必须是「真重算」。** 直接重跑同一 `(τ,conf)` 会命中缓存、立刻返回，
  看起来通过其实什么都没算。做法：把该缓存挪到不匹配 glob 的临时路径（保留备份），
  在用另一张空闲卡重算，逐位比较后保留新文件。本轮对 `(τ=1, conf=4150)`
  （原由 P100a 产出、在 P100b 上重算 363 s）得到 `array_equal=True`、
  `max|Δ|=0.0`、NaN 掩码与 contract SHA 全部相同——CuPy/P100 路径跨设备确定。
- **新 b 点没有逐点联合拟合，`m0` 必须走 `c2only`。** `b00_tsep_plateau.py`
  的 `--m0-source fit` 按 `fit["fits"][mom]["z{z}_b{b}"]` 取 `m0`，扩轴后新点
  没有这项，直接 `KeyError: 'z3_b3'`。`m0` 只由 C2 决定、与 `(z,b)` 无关，
  所以扩轴分析用 `--m0-source c2only`（其内部仍做退化检查：`m0∈(0.2,1.5)`、
  与其余窗口中位相差 <20%），并把 `m0_window="c2only"` 写进产物，读者才知道
  归一化用的是同一个常量。
- **后台脚本必须显式 `export PYTHONPATH=/root/PyQCD`。** 用绝对路径调脚本
  并不能让 `import pyqcd` 成功；本轮会话 cwd 在 `products/pipeline/data`，
  三条后台分析作业全部 `ModuleNotFoundError: No module named 'pyqcd'`，
  而主日志只留一条 traceback，容易被误读成脚本本身坏了。
- **长分析一定要 `python3 -u`。** 重定向到文件时 Python 默认块缓冲，几分钟内
  日志都是 0 字节，看起来像「进程没起来」；用 `ps` 看得到进程在跑，但拿不到
  任何进度。本轮 `b00_tsep_plateau.py` 的 `print` 没有 `flush=True`，
  `run_tau3.log` 因此在启动后一直是空的。

### 4.9 文件名、轴与派生数字只能有一个来源

- 本轮 `build_physics_dataset.py` 按模块自己的约定去读
  `P{mom}_tau{t}_b7_ratio.npz`，而真正写文件的是 `flow_time_scan.ratio_at`，
  落盘名是 `P{mom}_tau{t}_ratio.npz`。两者不一致**不会报错**，只会让表格变成
  空表加一条 `missing` 记录——比崩溃更难发现。约定是「生产者定义文件名，
  消费者从生产者取」，不要在两处各写一遍。
- 同理，模块级常量（`B_LIST`、`TSEPS`、`C2_TMIN/C2_TMAX`）被多个脚本复用时要
  显式赋值并**从产物元数据反查**：C3 缓存里存了 `b_list` 与 `flow_tau`，下游就该
  以它为准，而不是相信自己的默认值。
- 派生量（窗内点集、交集、计数）每次都要从产物重算。本轮一处「三流时共同窗只有
  4 个点」的说法来自上一阶段的临时检查（当时只看了 `z=5,6`），按完整 `z=0..12`
  重算是 **16 个点**。跨会话沿用数字会让后续分析白丢 3/4 的统计量。
- **provenance 路径要用解析后的绝对路径。** 产物里的 `cache` / `m0_source` 字段
  直接记录命令行传入的字符串：同一条命令在别的 cwd 下用相对路径重跑，数值
  4290/7970 个字段全等、只有这几个字符串不同，`cmp` 就会判「不同」。
  幂等性检查要么统一用绝对路径，要么先剥离 provenance 字符串再比较。

## 5. 数据审计经验（极值 / 方差 / 均值）

判读前先跑 [`data_audit.py`](../../data/runs/tmd-recompute-20261028/products/next-round-20261029/data_audit.py)：

- 误差字段不得为负、不得恒为零；`NaN`/`Inf` 一律要先归类。
- `χ²/dof` 越界、设计矩阵条件数超过 `1e10`、比值出现 `1e6` 量级大值，都要先回到
  产生该字段的脚本排查。
- 大值必须能归因到已知机制：P400 的 C2 在 `t/a≥7` 后趋零，|R| 的尾部放大不是信号。
- 窗口误差应由 JK 样本独立重算并与已存值逐格一致（本轮 6 个已发布文件差 **0.0**，
  390/780 格点）。
- **JK 样本的轴顺序要单独验。** 删除一法复制品的均值不必等于点估计（比值是非线性
  统计量），但偏差应当在噪声之下：本轮 `|mean(JK)-R|/err_JK` 中位 0.014、p99 0.09、
  最大 0.28（P400 分母趋零处）。若样本轴与 observable 轴混序，这个比值会在
  所有格点上 O(1)，而「误差由样本重算」依然会通过——所以这两条检查不能互相替代。
- ratio-v3 在插入时间超过 `tsep` 的格点**按约定写 NaN**（1D 975/4290，2D 1950/8580）。
  审计要先核对 NaN 掩码与 `insertion > tsep` 逐格一致；把「有 NaN」直接当硬错误会
  淹没真问题。本轮的 NaN 掩码全部符合约定，最终硬错误 0 条。
- 检查器自身也要参数化。tsep 扩到 24 的 C3 缓存形状是
  `(z,b,tsep=20,insertion=25)`，而审计里写死「轴长 6、tseps=5..10」的版本对不上轴，
  把 12350 个约定内的 NaN 误报成 4 条硬错误。改为从 NPZ 的 `tseps` 数组推导轴映射后
  归零。**审计器的轴假设必须与产物的轴约定同源。**
- 越界要分级：C2-only 单指数拟合在 `t=1…10` 上 `χ²/dof` 高到 225，这是缺激发态的
  已知模型不足，标 `info`；两态联合拟合出现同样数值才是真张力。
- 只给 min/max/mean 不够，还要把极端值与物理机制逐一对上；否则审计只是打印。
- `status`/`physical_acceptance` 只写在**结果**产物里；`workers/*.json` 与
  `cupy_backend_check*.json` 是作业/设备日志，记录「哪张卡跑了什么、跑了多久」，
  没有物理状态字段。收尾检查要把这两类分开统计，否则会把日志误报成缺状态字段。
