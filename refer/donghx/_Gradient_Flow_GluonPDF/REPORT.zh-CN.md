# Quark gradient flow：显式 dp 路径性能测试

测试结论基于真实 L24x72 输入和完整生产收缩指标。当前生产已使用 opt_einsum optimal；本测试比较路径优化器及显式路径，不改变算符。

GPU任务 4016174，设备 NVIDIA A100-SXM4-80GB，节点 gpu025.snsc.cn。
CuPy 14.1.1，NumPy 2.2.6，opt_einsum 3.4.0。
CPU独立正确性任务4016165已通过。GPU每个模式预热一次、正式三轮，轮次交替正反顺序，计时前后同步GPU。

conf30000，NE150、NV650、16个z长度、2个z方向、4×4插入旋量，Pz=0,±4,±5,±6。

## 正确性和路径证据

全部模式对照已保存生产输出，C2、逐个六Wick项、总C3以及三个通道投影均通过，最大相对L2差 1.025e-14，阈值2e-10。
CPU另用独立完整旋量C2、六Wick项和未因子化时间求和C3对照；覆盖不同形状和动量批大小。
路径由实际形状生成并转换为tuple，再显式传入contract_expression。缓存键为指标式、形状、optimizer。
每个case实际路径、FLOPs、最大中间张量和逐式规划时间保存在results/plans_case*.json。

## 可用于生产决策的结论

- 样本0：C2 reduced耗时降低2.15%；C2 reference降低6.79%；C3降低0.82%；C3+C2两种收缩合计降低0.97%。
- 样本1：C2 reduced耗时降低2.44%；C2 reference降低6.83%；C3降低0.73%；C3+C2两种收缩合计降低0.84%。

单纯更换为dp没有复现pol_2pt第20节中由greedy切换带来的1.6×加速；当前quark-flow基线已经是optimal。
dp可以减少首次规划开销，热执行收益按上表实测理解，不能外推为整个conf的倍数提速。
本测试只直接测L24x72。三ensemble的spin2_contractions.py逐字节一致，但L32输入维度/时间窗不同，不能把当前数值加速比直接移用。
现有生产脚本、manifest和任务均保持原版本。候选实现位于explicit_contract.py，可在后续独立版本中复用。
