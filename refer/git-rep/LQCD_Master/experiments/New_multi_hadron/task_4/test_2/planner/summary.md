This revised plan keeps the original physics target intact: a single zero-momentum `multi_hadron_2pt` correlator for the local nine-quark operator built from the three literal single-term baryon blocks `(u^T Cg5 d)d`, `(u^T Cg5 d)u`, and `(u^T Cg5 d)s`. The key correction is that the measurement is now encoded as one combined non-factorized contraction object that explicitly uses both required propagators, rather than two separate partial correlators that could not represent the full nine-quark observable.

The operator content is now machine-readable at the correlator level. Both source and sink carry the full composite operator together with the ordered list of baryon blocks, and each block has its own explicit `P_plus = (1 + gamma4)/2` projector. This fixes the main physics ambiguity in the previous version: the requested projection is part of the observable definition and is no longer left only as prose.

The baryon metadata have also been tightened to match the stated single-term requirement. In particular, the `uds` block is typed as a literal local single-term baryon block, not as an octet/Lambda template, so downstream code generation is steered away from unwanted flavor-combined Lambda constructions. The propagator content remains minimal and physically correct: one light point-source solve reused for all `u/d` lines by isospin symmetry, plus one strange point-source solve for the `s` line, both using the requested stout-smeared links for inversion.

To preserve consistency with the fixed ensemble information, the `ensemble:` block is kept unchanged exactly as supplied. At the same time, the executable 8-rank runtime layout requested by the user is now encoded directly inside the correlator execution metadata as `mpi_ranks: 8` and `grid_size: [1,1,2,4]`, so an executor can launch the correct decomposition without relying on a prose-only override. Finally, the output is made executable by specifying a concrete plain-text file target in the run directory with columns `(t, ReC, ImC)`.
