This revised plan keeps the original physics target intact: a single `multi_hadron_2pt` measurement for the local nine-quark operator
`[(u^T Cg5 d)d] * [(u^T Cg5 d)u] * [(u^T Cg5 d)s]`
at zero momentum, using only the requested single-term baryon blocks. The central correction is that the source and sink are now encoded as one explicit combined 9-quark operator with a fixed ordered block list `udd -> uud -> uds`, and the correlator explicitly references that same composite operator on both ends. This removes the earlier ambiguity that could have let an executor treat the task as a product of separate baryon correlators instead of one unified nine-quark Wick contraction.

The parity prescription is also made machine-actionable. Each baryon block now carries `source_projector: P_plus` and `sink_projector: P_plus`, and the combined operator plus the measurement record both repeat the per-block projector structure. That makes the intended spin projection unambiguous: `P_plus=(1+gamma4)/2` is applied separately to each baryon block, not once at the composite 9-quark level.

For the propagators, the plan stays minimal and physically appropriate. Because the operator contains only `u`, `d`, and one `s` line, it needs one forward light propagator reused for all `u/d` quark lines by isospin symmetry and one forward strange propagator for the `s` line. Both are computed from the common point source at `[0,0,0,0]` using stout-smeared gauge links with `(n_steps=1, rho=0.125, ndim=4)` exactly as requested.

The runtime setup is clarified without altering the supplied ensemble facts. The `ensemble:` block is preserved consistently with the fixed configuration data, while the actual execution layout required by the task is stated explicitly in a dedicated `runtime:` section as `8` MPI ranks with `grid_size [1,1,2,4]` on `2` nodes times `4` GPUs. The output remains a plain-text correlator file written in the run directory, with a concrete filename for the given configuration.
