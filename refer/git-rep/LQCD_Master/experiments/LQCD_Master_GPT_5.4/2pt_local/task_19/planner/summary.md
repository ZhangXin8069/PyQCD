## Revised plan summary

This revision keeps the original task structure and user-requested setup, but closes the main physics and execution gaps.

The calculation is now stated explicitly as a **zero-momentum baryon 2pt in the local dcc doubly charmed channel** built from
\[
\mathcal O(x)=\epsilon^{abc}(d^{Ta}(x) C\gamma_5 c^b(x))c^c(x),
\]
with the **positive-parity projector**
\[
T_{\mathrm{mat}}=\frac{1+\gamma_t}{2}.
\]
This makes clear that the task targets the local spin-1/2 positive-parity channel generated by the requested operator, while also honestly labeling the run as a **smoke test** rather than a precision spectroscopy result, since no independent heavy-quark tuning validation is provided here.

The propagator/measurement chain is fixed so the YAML is executable: the baryon correlator now depends on **both** required propagators,
- one light propagator for the down quark,
- one charm propagator reused on the two identical charm lines.

The revision also makes the **identical-charm exchange structure explicit**: the contraction must include both the direct and exchange Wick topologies with the proper fermionic sign. This was a real missing correctness item in the previous version.

The solver strategy is separated by flavor. The light solve may use the ensemble multigrid setup, but the charm solve is no longer presented as automatically using the same MG hierarchy. Instead, the plan specifies a **standard non-MG charm solve unless charm-MG validation exists**, and it explicitly records that the charm mass/setup should be treated as **test-level** for this task unless heavy-quark systematics have been validated elsewhere.

The observable formation chain is now explicit:
1. invert light and charm propagators from the point source `[0,0,0,0]` on the stout-smeared links,
2. build the dcc baryon 2pt including identical-charm exchange,
3. apply the positive-parity projector,
4. sum over spatial sink coordinates for zero momentum,
5. reduce to a scalar function of Euclidean time,
6. save the final correlator.

The output requirement is promoted into the machine-readable plan: save a plain text file in the run directory as
`./xi_cc_dcc_2pt.txt`
with exactly three columns:
`t Re Im`
and **no header or extra text**.

Finally, a minimal validation checkpoint is added: both light and charm solver residuals must be checked, and the projected correlator must pass a basic sanity test such as being finite and showing plausible Euclidean-time decay behavior before the output is accepted as usable.
