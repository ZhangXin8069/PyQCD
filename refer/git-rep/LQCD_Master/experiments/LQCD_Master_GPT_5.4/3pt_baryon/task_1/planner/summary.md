This revision restores the original physics target as the full proton three-point correlator for the flavor-diagonal current \(J_x=\bar u\gamma_x u\), rather than silently narrowing the task to the connected piece. Because the current is flavor diagonal, the plan now separates the calculation into a connected sequential-source contribution and a disconnected light-quark loop contribution, and it defines the final observable as their sum.

For the connected part, the proton source and sink are both the standard local \(\epsilon^{abc}(u^T C\gamma_5 d)u\) operator at zero momentum with the positive-parity projector \((I+\gamma_t)/2\). The forward light propagator is solved from the requested point source at `[0,0,0,0]` on stout-smeared links with `(n_steps=1, rho=0.125, ndim=4)`. The sequential propagator is now specified correctly: it is built from the full proton sink block on the entire sink timeslice at `t_sink = 8`, with zero sink momentum and the two-dagger convention, and then inverted with the same light-quark Clover operator. The code-generation inputs are fully pinned down as `uud -> uud`, `current_quark = u`, `current_antiquark = u`, `current_gamma = gamma_x`, `projector = P_plus`, `diquark gamma = Cg5`, `tseq = 8`.

For the disconnected part, the plan adds the required stochastic light-quark loop for \(\sum_{\vec z}\mathrm{Tr}[\gamma_x S_l(z,z)]\). This is combined with the proton source-to-sink baryon block at the same source-sink separation, but that internal baryon block is not saved as a standalone two-point observable, so the instruction not to compute a separate 2pt output is respected.

The measurement chain is now closed explicitly: the connected correlator requires the forward light propagator, the sequential light propagator, the local \(\gamma_x\) insertion, and the spatial sum over insertion time; the disconnected correlator requires the stochastic loop and the internal proton baryon block at `tseq = 8`; the final saved observable is the sum of connected and disconnected pieces. The output contract is tightened to exactly one plain `.txt` file in the run directory, rank-0 only, no header, with fixed columns `tseq  t_ins  Re  Im`.

Numerically, this remains a minimal raw-data production setup: a single point source, local sink, and only `tseq = 8` are sufficient to generate the requested correlator but are not enough to control proton excited-state contamination for later matrix-element extraction. That caveat is now stated explicitly so the output is not over-interpreted.
