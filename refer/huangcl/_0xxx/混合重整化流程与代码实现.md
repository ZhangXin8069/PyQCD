# 裸矩阵元 c0 之后的混合重整化流程

## 文档范围

本文分析的对象是:

- 本地参考代码: `/public/home/huangcl/04_gluon_unpolarized_PDF/99_ref_code`
- 原始代码目录: `/public/group/imp/zengch/LQCD/renorma`
- 对应文章: arXiv:2510.26425v2, "Unpolarized gluon PDF of the nucleon from lattice QCD at physical point in the continuum limit"

本文只做代码和文章公式的静态对照, 没有重新运行 3000 个 bootstrap 样本, 也没有重新产生最终物理结果. 文中的代码行号以本地 `99_ref_code` 快照为主, 并与原始目录中同名文件做了对照.

## 一句话结论

代码不是在做 RI/MOM 重整化. 它采用的是文章中的 hybrid renormalization:

1. 先把每个 `z`, 每个 `Pz` 的 c0 组装成裸矩阵元 `hB`.
2. 用所有 bootstrap 样本分别除以同一样本的 `z=0` 矩阵元, 得到归一化裸矩阵元 `hB^n`.
3. 用五个格距的 `Pz=0` 数据联合拟合自重整化因子 `Z_R(z,1/a,mu)`.
4. 短距离用 `hB^n(z,Pz)/hB^n(z,0)` 做 ratio scheme.
5. 长距离用 `hB^n(z,Pz)/Z_R(z,1/a)` 做 self-renormalization.
6. 用 `eta_s` 保证短距离和长距离两支在 `z_s` 处连续.
7. 对 `h_R(lambda=zPz)` 做大 lambda 外推, 再做 Fourier transform 得到 quasi-PDF.
8. 用一圈微扰 matching kernel 把 quasi-PDF 转成 light-cone PDF.
9. 最后做 `a -> 0`, `Pz -> infinity`, `m_pi -> m_pi,phys` 的联合外推.

## c0 的含义

文章 supplemental 中的有效矩阵元定义为

$$
\Delta R(P_z,z,t_{\mathrm{sep}})
=
\frac{\sum_{t=t_r}^{t_{\mathrm{sep}}+1-t_r}
C_{3pt}(P_z,z;t,t_{\mathrm{sep}}+1)/C_{2pt}(P_z,t_{\mathrm{sep}}+1)}
{\sum_{t=t_r}^{t_{\mathrm{sep}}-t_r}
C_{3pt}(P_z,z;t,t_{\mathrm{sep}})/C_{2pt}(P_z,t_{\mathrm{sep}})}
-
1
$$

在忽略更高激发态后,

$$
\Delta R(P_z,z,t_{\mathrm{sep}})
\approx h_B(z,P_z)+c_1 t_{\mathrm{sep}}e^{-\Delta E t_{\mathrm{sep}}}
$$

当 `t_sep` 足够大时, 对 `t_sep` 做常数拟合:

$$
\Delta R(P_z,z,t_{\mathrm{sep}})\approx h_B(z,P_z)
$$

代码中的 `c0` 就是这个常数拟合的 plateau 值. 对应实现是:

- `fit_ratio_FeynmenHellman_new_MPI.py:28-99`
- 每个 `z`, 每个 `Pz`, 每个 bootstrap 样本单独对 `t_sep` 做常数拟合
- CSV 列为 `sample_i,c0,chi2_mean`
- 典型文件形状为 `(3000, 3)`, 即 3000 个 bootstrap 样本

因此后续流程中可以把 `c0(z,Pz)` 直接视为 `h_B(z,Pz)` 的样本表示.

## 从 c0 到归一化裸矩阵元 hB^n

### 代码的归一化

`hB_data_FeynmenHellman_new.py:33-110` 完成这一步. 对第 `s` 个 bootstrap 样本:

$$
h_{B,zn}(z_i,P_z;s)=c_0(z_i,P_z;s)
$$

$$
h_B^n(z_i,P_z;s)
=
\frac{h_{B,zn}(z_i,P_z;s)}
{h_{B,zn}(z_0=0,P_z;s)}
$$

其中

- `z_i = i a`
- `a` 在代码中先以 `GeV^{-1}` 存储, 再乘 `0.197` 转成 fm
- `i=0,...,19`
- `hB_o_zn` 是未归一化数组
- `hB_o` 是除以 `z=0` 后的归一化数组
- `hB` 和 `loghB` 是插值到固定 `z` 网格后的数组

代码随后对每个 bootstrap 样本沿 `z` 轴做线性插值:

$$
z \in \{0.15,0.20,0.25,\ldots,1.00\}\ \mathrm{fm}
$$

因此 `z=0` 只用于归一化, 不进入 `Z_R` 拟合.

## 自重整化因子 Z_R 的拟合

### 文章公式

文章 Eq. (6) 定义:

$$
Z_R(z,1/a,\mu;k,\Lambda_{\mathrm{QCD}},m_0,d)
=
\exp\left[
\frac{kz}{a\ln(a\Lambda_{\mathrm{QCD}})}
+m_0z
+\frac{5C_A}{3b_0}
\ln\frac{\ln(1/(a\Lambda_{\mathrm{QCD}}))}
{\ln(\mu/\Lambda_{\mathrm{QCD}})}
+\frac{1}{2}\ln\left[\left(1+\frac{d}{\ln(a\Lambda_{\mathrm{QCD}})}\right)^2\right]
\right]
$$

其中

- 第一项是线性发散
- `m0 z` 是有限质量项带来的重整化歧义
- 后两项是 leading 和 subleading 对数发散的重求和
- `k` 与具体离散作用量有关
- `d` 和 `m0` 通过短距离 continuum matching 确定
- 文章使用 `mu=2 GeV`
- `nf=3`, `b_0=11-2nf/3=9`

短距离的 MSbar 微扰结果为

$$
h_{\overline{\mathrm{MS}}}^{\mathrm{pert}}(z,\mu)
=
1+\frac{\alpha_s(\mu)C_A}{4\pi}
\left[
\frac{5}{3}\ln\frac{z^2\mu^2}{4e^{-2\gamma_E}}+3
\right]
$$

代码对应函数是 `fit_zr_new.py:39-48` 的 `Z_MS`.

### 联合拟合形式

文章 Eq. (8):

$$
\ln h_B^n(z,P_z=0,1/a)
=
\ln Z_R(z,1/a,\mu)
+
\begin{cases}
\ln h_{\overline{\mathrm{MS}}}^{\mathrm{pert}}(z,\mu), & z_0\le z\le z_1\\
g(z)-m_0z, & z_1<z
\end{cases}
$$

其中

- `z0=0.15 fm`
- `z1=0.3 fm`
- `z` 最大到 `1 fm`
- `g(z)` 在离散 `z` 网格上作为独立自由参数拟合

### 代码实现

`fit_zr_new.py:50-122` 的 `th_hB` 实现了代码版本:

$$
\ln h_B^n(z,P_z=0,1/a)
=
\frac{k z_{\mathrm{GeV}}}{a\ln(a\Lambda_{\mathrm{QCD}})}
+\frac{5C_A}{3b_0}
\ln\frac{\ln(1/(a\Lambda_{\mathrm{QCD}}))}
{\ln(\mu/\Lambda_{\mathrm{QCD}})}
+\frac{1}{2}\ln\left[\left(1+\frac{d}{\ln(a\Lambda_{\mathrm{QCD}})}\right)^2\right]
+f_1a+f_2a^2
+B(z)
$$

短距离分支:

$$
B(z)=\ln Z_{\overline{\mathrm{MS}}}^{\mathrm{pert}}(z,\mu)
+(m_0+m_2a^2)z_{\mathrm{GeV}}
$$

长距离分支:

$$
B(z)=g_j
$$

这里的 `g_j` 就是 `g1,...,g14`.

`fit_zr_new.py:84-99` 中的分界条件是:


因为 `z_i` 已经转换成 `GeV^{-1}`, 所以这等价于 `z <= 0.301 fm`. 固定网格为 `0.15,0.20,...,1.00 fm`, 因此:

`z0` 没有单独写成一个 mask, 因为数据数组本身就是从 `0.15 fm` 开始的.

### 为什么代码中的 m0 只出现在短距离分支

文章 Eq. (8) 的长距离分支是 `g(z)-m0 z`, 而 `Z_R` 本身也含 `m0 z`, 两项在长距离相消. 代码把这个相消提前做掉:

- `th_hB` 的长距离分支直接使用 `g_j`
- `th_hB` 的短距离分支显式保留 `m0 z`

因此代码中的 `g_j` 对应文章中的 `g(z)`, 不需要再额外减一次 `m0z`. 后面 `th_ZR` 仍然显式返回包含 `m0z` 的完整 `Z_R`, 用于长距离除法.

### 拟合细节

- 使用 `loghB`
- 每个 ensemble 的卡方为

$$
\chi_i^2=(\ln h_{B,i}^{n}-\ln h_{B,i}^{n,\mathrm{th}})^T
C_i^{-1}
(\ln h_{B,i}^{n}-\ln h_{B,i}^{n,\mathrm{th}})

\frac{\sum_i \chi_i^2}

`C32P29` 数据在 `fit_zr_new.py:32-37` 中加载了, 但在 `cost_function_all` 中对应项被注释掉. 当前联合拟合实际使用的是五个格距的 `L24x72`, `L32x64`, `L32x96`, `L36x108`, `L48x144` 数据集.

## 坐标空间的 hybrid renormalization

### 文章公式

文章 Eq. (5):

$$
h_R(z,P_z)=
\frac{h_B^n(z,P_z,1/a)}
{h_B^n(z,P_z=0,1/a)}
\theta(z_s-|z|)
+
\eta_s
\frac{h_B^n(z,P_z,1/a)}
{Z_R(z,1/a)}
\theta(|z|-z_s)
$$

其中 `z_s` 是短距离和长距离的分界. 工作值通常为 `0.3 fm`. 文章还通过 `z_s=0.2 fm` 和 `0.3 fm` 的差异估计系统误差.

### 代码实现

`fit_hR_big_lambda_new.py:117-158` 的 `hR_z_Pz` 是核心:

```python
mask = (z_ < zs)
res[mask] = hR_pz[mask] / hR_0[mask]
eta_s = ZR_fit[~mask][0] / hR_0[~mask][0]
res[~mask] = (hR_pz[~mask] / ZR_fit[~mask]) * eta_s
```

变量对应关系:

- `hR_pz`: `h_B^n(z,P_z)`
- `hR_0`: `h_B^n(z,P_z=0)`
- `ZR_fit`: 由 `th_ZR` 在同样 `z` 网格和所有 bootstrap 样本上计算的 `Z_R(z,1/a)`
- `zs`: 从 JSON 配置读取的 `zs_input`
- `eta_s`: 每个 bootstrap 样本各有一个值

`eta_s` 的公式为

$$
\eta_s=
\frac{Z_R(z_s,1/a)}
{h_B^n(z_s,P_z=0,1/a)}
$$

它保证在 `z_s` 处短距离支和长距离支相等. 代码实际使用第一个满足 `z > z_s` 的离散点来计算 `eta_s`, 不是在连续 `z_s` 上做插值:

```python
eta_s = ZR_fit[~mask][0] / hR_0[~mask][0]
```

因此如果 `z` 网格改变, 或者 `z_s` 恰好落在两个网格点之间, `eta_s` 会随第一个长距离点的选择而略有变化. 这是复现时需要注意的离散化约定.

### 分支边界

代码使用严格小于:

```python
mask = (z_ < zs)
```

因此:

- `z < z_s` 走 ratio scheme
- `z >= z_s` 走 self-renormalization

文章公式写作 `theta(z_s-|z|)` 和 `theta(|z|-z_s)`, 在 `z=z_s` 处的定义本身有边界歧义. 当前网格通常没有精确落在 `0.3 fm` 上, 所以实际影响较小, 但重写代码时应显式规定边界.

### 输出

`hR_z_Pz` 返回:

- `lambda_ = z_GeV * Pz_GeV`
- `res = h_R(z,P_z)`

`res` 保留 bootstrap 样本轴, 形状为 `(Nz,Nsamples)`. 这个数组不会单独写成 `hR_z` 文件, 而是直接送入后续 `lambda` 外推.

## 一圈微扰 matching

### 连续公式

文章 Eq. (13):

$$
x\tilde g(x,P_z)
=
\int_{-\infty}^{\infty}\frac{dy}{|y|}
C_{\mathrm{hybrid}}
\left(
\frac{x}{y},\lambda_s,\frac{\mu}{yP_z}
\right)
\, y g(y,\mu)
$$

其中:

- `C_hybrid` 是 momentum-space matching kernel
- `lambda_s = z_s P_z`
- `mu=2 GeV` 为默认重整化标度

文章 supplemental 将 ratio-scheme kernel 写成分段形式. 去掉公共因子后, 代码中的三个分段函数为:

$$
g_1(\xi)=
-\frac{2(1-\xi+\xi^2)^2}{1-\xi}
\ln\frac{\xi}{\xi-1}
-\frac{11-28\xi+18\xi^2-12\xi^3}{6(1-\xi)},
\quad \xi<0
$$

$$
g_2(\xi)=
\frac{2(1-\xi+\xi^2)^2}{1-\xi}
\left[
-\ln\frac{\mu^2}{4y^2P_z^2}+\ln(\xi(1-\xi))
\right]
-\frac{15-56\xi+102\xi^2-96\xi^3+48\xi^4}{6(1-\xi)},
\quad 0<\xi<1
$$

$$
g_3(\xi)=
\frac{2(1-\xi+\xi^2)^2}{1-\xi}
\ln\frac{\xi}{\xi-1}
+\frac{11-28\xi+18\xi^2-12\xi^3}{6(1-\xi)},
\quad \xi>1
$$

hybrid 修正项为:

$$
g_0(\xi)=
\frac{5}{6}
\left[
-\frac{1}{|1-\xi|}
+
\frac{2\mathrm{Si}((1-\xi)|y|\lambda_s)}
{\pi(1-\xi)}
\right]
$$

代码把总 kernel 拼成:

$$
g(\xi)=
\begin{cases}
-g_0(\xi)-g_1(\xi), & \xi<0\\
g_0(\xi)+g_2(\xi), & 0<\xi<1\\
g_0(\xi)+g_3(\xi), & \xi>1
\end{cases}
$$

其中

$$
\xi=\frac{x}{y}
$$

### 代码实现

`matching_MPI.py:36-140` 是生产版本. 主要步骤为:

1. 读取 `hR_x` 并线性插值到目标 `x` 网格.
2. 计算 `Pz_GeV = Pz * 2*pi/(N_l*a_len)`.
3. 计算 `lambda_s = 0.3/fm_to_GeV * Pz_GeV`.
4. 构造 `x_i/y_j` 和 `xi=x_i/y_j` 矩阵.
5. 实现 `g_1,g_2,g_3` 的 ratio-scheme kernel.
6. 实现 `g_0` 的 hybrid 修正, 其中使用 `scipy.special.sici` 的 `Si`.
7. 用 `g_xy` 和 `M_alp_LO` 实现 plus prescription.
8. 解 matching matrix.
9. 保存 `hR_PDF`.

代码中的分段为:

```text
xi < 0:        -g0 - g1
0 < xi < 1:     g0 + g2
xi > 1:         g0 + g3
xi = 1:         不赋值, 保持 0
```

`xi=1` 恰好是 `x=y` 的对角线, 这里不直接计算 `1/(1-xi)`. 接触项和对角线修正由

```python
M_alp_LO = g_ij / y_matr \
           - delta_ij * y_matr * np.sum(g_ij / y_matr**2, axis=1)
```

以及

```python
C_alp_LO = dx_matr * alpha_s * CA / 2. / pi
z_ij = delta_ij + C_alp_LO @ M_alp_LO
hR_PDF = np.linalg.inv(z_ij) @ hR_0
```

实现. 这里:

- `dx_matr = diag(sign(x)) * dx`
- `alpha_s = A_s(mu) * 4*pi`
- `A_s(mu)` 来自 `/public/home/zengch/All_TMD_dependence/constant.py`
- `CA=3`
- `M_alp_LO` 是离散化的 plus-prescription 修正
- `z_ij` 是离散 matching matrix
- `hR_0` 是 Fourier transform 后的 quasi-PDF
- `hR_PDF` 是 matching 后的 light-cone PDF

生产代码使用 MPI 并行. `matching_MPI.py:142-167` 用 MPI rank 选择 ensemble:

```python
conf_set = ['L24x72', 'L32x64_C32P23', ...]
conf = conf_set[rank_]
```

因此运行时 rank 数和 `conf_set` 长度必须匹配.

`x` 网格在 `matching_MPI.py:163-167` 中为:

```python
dx = 0.02
x_test = np.arange(-1.99, 1.99 + 0.005, dx)
```

这个网格故意避开了 `x=0`, 因为 `dx_matr` 中有 `x/abs(x)`.

输出文件为:

```text
result/hR_PDF/{conf}{note}{append_note}_FeynmenHellman_mu{mu}pz{Pz}.npz
```

键为:

- `x`
- `hR_PDF`
- `hR_tilde`

抽查 `L24x72_dhxmeang2_Nremovenew11_FeynmenHellman_mu2.0pz4.npz`:

- `x`: `(200,)`
- `hR_PDF`: `(200,3000)`
- `hR_tilde`: `(200,3000)`

## 最后的 continuum, infinite-Pz 和 physical-pion 外推

`fit_pz_a_extrapolatiing.py:40-205` 是最后一步.

代码首先:

```python
xx = data['x']
hR_PDF = data['hR_PDF'] * 2
mask = (xx >= 0) & (xx <= 1)
```

也就是:

- 对 matching 后的 `hR_PDF` 乘 2
- 只保留正 `x` 的 `[0,1]` 区间
- 每个 `x` 点独立拟合
- 每个 bootstrap 样本独立拟合
- 用各 ensemble, 各 `Pz` 的样本构造协方差

拟合形式在 `fit_pz_a_extrapolatiing.py:32-38`:

$$
xg(x,P_z,a,m_\pi)
=
xg_0(x)
+a^2f(x)
+a^4l(x)
+a^2P_z^2h(x)
+\frac{d(x)}{P_z^2}
+\frac{b(x)}{P_z}
+k(x)(m_\pi^2-m_{\pi,\mathrm{phys}}^2)
+c(x)e^{-L a m_\pi}
$$

当前代码固定:

```python
m.fixed['lx'] = True
m.fixed['hx'] = True
m.fixed['bx'] = True
m.fixed['cx'] = True
```

因此默认拟合主要保留 `xg0`, `a^2 f`, `d/Pz^2`, `k(m_pi^2-m_pi,phys^2)` 等项. 文章主文中 Eq. (10) 给出了更简化的形式:

$$
xg(x,P_z,a)
=
xg_0(x)
+a^2f(x)
+\frac{d(x)}{P_z^2}
+k(x)(m_\pi^2-m_{\pi,\mathrm{phys}}^2)
$$

并说明最终结果通过 AIC 对不同外推模型做组合. 本地 `fit_pz_a_extrapolatiing.py` 是其中一种具体模型的实现, 不是 AIC 组合本身的完整实现.

输出为:

```text
result/hR_res/new_res_mu2.0_gfdk_NremovenewXX_c.npz
```

保存字段包含:

```text
x, xg0, fx, lx, hx, dx, bx, kx, cx, chi2mean
```

## 代码审查中需要特别注意的地方

### 版本漂移

本地 `99_ref_code` 是原始目录的一个快照, 不是完全同步的最新版本. 已发现:

- `matching_MPI.py` 本地使用 `_Nremovenew10`, 原始目录最新为 `_Nremovenew11`
- `hB_data_FeynmenHellman_new.py` 和 `fit_ratio_FeynmenHellman_new_MPI.py` 中本地使用 `_dhxmeang2`, 原始目录最新使用 `_dhxmeang3`
- `fit_pz_a_extrapolatiing.py` 本地仍是较早的 `Pz>1.7 GeV` 选择, 原始目录最新版本改为 `Pz>2.0 GeV` 的 v2 选择

因此复现文章 v2 时应以原始目录当前版本和对应结果文件名为准, 不能只看本地 `99_ref_code` 的默认字符串.

### 硬编码路径

几乎所有脚本都写死了:

```python
this_path = '/public/group/imp/zengch/LQCD/renorma'
```

把代码复制到 `99_ref_code` 后, 脚本仍然会从原始目录读数据, 并且把结果写回原始目录. 这不是一个可以独立运行的本地副本.

`matching.py` 的非 MPI 版本还写死了一个具体输入文件:

```text
result/hR_x/L24x72_dhxmeang1_Nremovenew3_FeynmenHellman_mu2.0pz5.npz
```

如果要复用, 应优先使用 `matching_MPI.py` 的动态文件名逻辑, 或把输入路径显式配置化.

### Z_R 输出文件名不一致

`fit_zr_new.py:421-423` 写出的文件名是:

```text
ZR_a5_FeynmenHellman_new_mu2.0_Lambda_test.csv
```

但 `fit_hR_big_lambda_new.py:93-94` 读取的是:

```text
ZR_a5_FeynmenHellman_new_mu2.0.csv
```

两者不一致. 当前结果目录中已有手工整理后的 `ZR_a5_FeynmenHellman_new_mu2.0.csv`, 但重新运行 `fit_zr_new.py` 后不能直接接上 `fit_hR_big_lambda_new.py`, 需要改名或修改 `ZR_use`. 这是复现流程中最容易出错的一处. 另外, `fit_zr_new.py` 的 `__main__` 只调用 `fit_ZR_mean`, 结果目录中的 3000 行 CSV 来自逐样本 `fit_ZR` 路径或其他 runner. 直接运行该主文件不会自动产生完整的 bootstrap 拟合 CSV.

### 删除目录

`fit_ratio_FeynmenHellman_new_MPI.py:131-137` 在重新拟合前执行:

```python
if os.path.exists(c0_save_path):
    shutil.rmtree(c0_save_path)
```

这会删除整个已有输出目录. 在共享目录中重跑前应先确认路径和 `conf/note/Pz` 字符串, 否则可能覆盖其他人的结果.

### MPI rank 映射

`matching_MPI.py` 假设:

```text
rank 0 -> L24x72
rank 1 -> L32x64_C32P23
...
rank 7 -> L48x144
```

如果 `mpirun -np` 不是 8, 或者提交脚本的 rank 数和配置不一致, 部分 ensemble 不会被执行, 或者会访问越界索引. 提交前应检查 `conf_set` 长度和 `--ntasks` 是否一致.

### 矩阵求逆

`matching_MPI.py:127-131` 直接使用:

```python
hR_PDF = np.linalg.inv(z_ij) @ hR_0
```

这在数学上等价于解线性方程, 但数值上不如:

```python
hR_PDF = np.linalg.solve(z_ij, hR_0)
```

稳定. 特别是当 `z_ij` 的条件数较大时, 直接求逆可能放大误差. 这是实现层面的数值风险, 不是文章定义的物理流程.

### x=0

matching 的 `dx_matr` 使用:

```python
np.diag(xx / abs(xx)) * dx
```

如果 `x` 网格包含 0, 会出现 `0/0`. 生产代码通过:

```python
x_test = np.arange(-1.99, 1.99 + 0.005, 0.02)
```

避开了 0. 以后改网格时必须保留这个约束, 或者显式实现 `x=0` 的极限和接触项.

### z_s 和 mu 的硬编码

hybrid renormalization 的 `z_s` 在 `fit_hR_big_lambda_new.py` 中来自 JSON 的 `zs_input`, 但 `matching_MPI.py:69` 计算 `lambda_s` 时又写死了 `0.3/fm_to_GeV`. 如果只把 JSON 中的 `z_s` 改成 `0.2 fm` 而不改 matching, renormalization 和 matching kernel 使用的 `z_s` 将不一致. 同理, `matching_MPI.py:30` 默认写死 `mu=2.`, 做 `mu=2` 到 `4 GeV` 的标度系统误差时需要确认 matching 和 Z_R 使用同一个 `mu`.

### factor 2 约定

`fit_pz_a_extrapolatiing.py:67` 对 `hR_PDF` 统一乘 2:

```python
hR_PDF = data['hR_PDF'] * 2
```

这是一个明确的代码约定, 可能对应正负 `z` 两支或者 operator normalization. 如果重写流程, 必须保持与 Fourier transform 和 matching 相同的归一化, 不能只复制最后一行公式.

### 误差传播

代码保留 bootstrap 样本轴, 因此误差不是用线性误差传播得到的, 而是:

- `c0`: 每个 bootstrap 样本单独拟合
- `hB`: 逐样本归一化和插值
- `Z_R`: 逐样本拟合
- `eta_s`: 逐样本计算
- `lambda`: 逐样本拟合
- Fourier: 逐样本变换
- matching: 逐样本矩阵求解
- 最后外推: 逐样本拟合

这样做可以自动保留非线性变换带来的相关性. 但是不同步骤使用了不同的协方差近似:

- `Z_R` 拟合: 对角 bootstrap 误差
- `lambda` 外推: 完整 bootstrap 协方差
- 最终外推: 完整 bootstrap 协方差

比较结果时应确认具体步骤使用的是哪一种, 不能把不同步骤的误差定义混在一起.

## 建议的最小检查清单

如果要基于这套代码重做分析, 建议先检查:

1. 每个 ensemble 的 `z_o` 网格是否一致.
2. 每个 `z` 的 CSV 是否有完整的 3000 个 bootstrap 样本.
3. `hB_o_zn` 的 `z=0` 行是否严格归一化为 1.
4. `Z_R` CSV 是否包含 `k,d,m0,m2,Lambda_QCD,g1..g14,f1,f2` 全部列.
5. `th_ZR` 在 `z_s` 附近是否和 `hB^n(z,0)` 连续.
6. `hR_x` 和 `hR_PDF` 是否所有样本均为 finite.
7. matching matrix 的条件数是否过大.
8. `lambda_extra`, `lamb_do`, `lamb_up` 是否和对应 `Pz` 配置匹配.
9. 是否采用文章的 `mu=2` 默认值, 以及是否单独跑了 `mu=2` 到 `4 GeV` 的系统误差.
10. 是否重复了 `z_s=0.2 fm` 和 `z_s=0.3 fm` 的 hybrid 边界系统误差.
