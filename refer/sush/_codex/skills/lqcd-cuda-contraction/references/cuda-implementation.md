# 从 einsum 到专用 C++/CUDA

## 用实际形状比较候选树

随附的 `inspect_path.py` 使用 Python 3.10+ 和 `opt_einsum.contract_path(..., shapes=True)`，已在 opt_einsum 3.4 上验证。传入带显式输出的方程和按操作数顺序排列的尺寸。下面取 pion 两点函数的一条标量收缩，用不同的源、汇模数检查端口。

```bash
python scripts/inspect_path.py 'manb,cedf,bd,fn,ac,em->' \
    4x4x7x5 4x4x5x7 5x5 7x7 4x4 4x4 \
    --optimizers greedy dp --dtype complex128
```

路径相对于 skill 安装目录。工具接受正整数轴长和标量形状 `'()'`。每一步列出局部方程、结果尺寸，以及适合映射为批矩阵乘的指标。`oe_cost` 是优化器的符号成本。`model_peak_bytes` 假定调用方的所有输入常驻、每步写一份新结果、最后一次消费后释放临时量，且所有对象使用指定 dtype。真实工作区还取决于视图、别名、提升精度、pack、并发、cuBLAS 与内存池。这个模型只覆盖一张图的一棵树。较大网络可先比较 greedy 与物理分块后的较小子图，再决定是否对整图做组合搜索。[形状工具](../scripts/inspect_path.py)

## 指标与矩阵布局

看当前二元步骤自己的右端。两个输入共有且仍保留的指标组成批轴 $b$，共有且在此步消去的指标组成 $k$，从左、右输入分别保留的其余指标组成 $i,j$。只有在各轴尺寸、顺序和 stride 允许时才合并为 $M,N,K$。例如

$$
C_{bij}=\sum_k A_{bik}B_{bkj}.
$$

共享的 $b$ 可以是两个流的配对动量，也可以是第三个张量仍要使用的内部指标。对角抽取、单侧求和或尺寸为 1 的广播需先明确取数方式。空 $i$ 或 $j$ 对应向量乘法或点积。空 $k$ 进入逐元素乘法或外积。普通转置和厄米共轭在复数程序中给出不同结果。

先画实际内存中 stride 为 1 的方向。已是合适矩阵或其转置时保持视图。确需 pack 的张量，在同一次调用的所有消费者间复用。可将选取 gamma 支撑、投影或输入升精度融入一次 pack，保留独立的数值对照。

以 C 连续的复双精度 `A[M,K]`、`B[K,N]`、`C[M,N]` 为例，列主序 cuBLAS 可以直接计算 $C^T=B^TA^T$。这里每个数组的字节原样传入，三个转置都由内存解释完成。

```cpp
// h is bound to the caller's stream. one and zero are host cuDoubleComplex scalars.
cublasStatus_t status = cublasZgemm(h, CUBLAS_OP_N, CUBLAS_OP_N,
                                   N, M, K, &one, B, N, A, K, &zero, C, N);
```

有 padding、不同轴序或显式共轭时重新推导 leading dimension、操作标志和 batch stride。批跨度以元素计，地址偏移和工作区容量用足够宽的整数。对不能在整批保持恒定步长的布局，可在地址规律改变处拆批、使用指针数组或显式重排。

## 调度、缓存和显存

- 对每个中间量记录生产者、最末消费者、元素数、布局、dtype 和依赖的外部轴。为所选拓扑顺序计算同时存活字节。跨动量复用的中间量应存活到最后一个消费批次。把通道批宽作为性能变量，在每张卡的实际余量内比较预存与重算。
- 对固定网络，可离线导出操作列表和输出系数，再由 C++ 在创建 plan 时定形并分配工作区，执行时只绑定本次指针。按设备、流、尺寸、布局或约定的连续性、精度、投影和返回模式匹配 plan。每次原生调用检查 CUDA/cuBLAS 错误。异步内核错误也需要在约定的完成点传回 Python。
- 可用 `extern "C"` 暴露创建 plan、执行、销毁和查询错误的接口，经 `ctypes` 连接 CuPy 或使用项目的扩展机制。将 cuBLAS handle 绑定到调用流，并给并发调用各自的工作区或串行化其访问。说明计算在何处同步，确保非连续视图的临时拷贝和跨卡收发缓冲区持有到完成。后一批覆写同一指针时，所有派生的数值中间量均应按其依赖更新。
- 多卡优先分配独立的外部通道，记录每卡工作区、P2P/经主机传输以及输出拼接轴。切在求和指标上时需要做数值归约并重新检查相消误差。两张卡的显存独立，聚合容量不能作为单次分配上限。

## 用热点决定写什么内核

完整算式中先跑 cuBLAS 的复 GEMM 基线。对许多等形状小矩阵测 strided batched 或合并成宽矩阵的实际成本。对 $M,N$ 很小而 $K$ 很长的点积，可测合并访存、块内归约和二阶段累加。对重排带宽热点，可测共享内存分块转置。每次对照包含新内核带来的临时拷贝和后续消费者开销。

大 GEMM 的候选之一是三个实 GEMM。设 $P=A_rB_r$、$Q=A_iB_i$、$R=(A_r+A_i)(B_r+B_i)$，结果为 $(P-Q)+i(R-P-Q)$。它引入额外的实数平面与相消，对用户请求的精度、输入分布和带符号图和分别验收后，再决定是否保留。

一条简单的跨通道复用例子是 quark loop `menf,Lfn,em->L`。先做 $U_{nf}=\sum_{me}\Gamma_{em}P_{menf}$，每个链长 $L$ 再做 $b_L=\sum_{nf}V_{Lfn}U_{nf}$。可将 $U$ 按 $(f,n)$ 写出以匹配 $V$ 的连续布局。同一个 $P,\Gamma$ 下，这次旋量归约只做一次。这个点积按原式直接相乘，使用复数 BLAS 时应核对共轭标志。[原始算式](/public/home/sush/distillation/lqcddb_update/src/lqcddb/test/contraction.pi.py)

## 判断算力余量

在相同算术模式下，对相近 $M,N,K$、批宽和精度测 GEMM，对 pack 尺寸测有效显存带宽。记录 CUDA/cuBLAS、GPU 型号、实际数学模式（含 TF32/Tensor Core）以及 Nsight 时间线或 CUDA events 的测量边界。端到端计时还需要 CPU 墙钟和参与的全部流、设备的完成事件。

标准复数 GEMM 常按 $8BMNK$ 个等效实 FLOP 计，三实乘法的主乘加按 $6BMNK$ 计，加减和 pack 另计。只对真正执行的、已经跨图去重的节点求和。对一条固定路径，按同一硬件口径估算 $t_{\rm elapsed}\geq\max(F/P_{\rm peak},D/BW_{\rm peak})$，其中 $F$ 与峰值采用同一实数运算口径，$D$ 是至少要从所计存储层搬运的字节数。用微基准的实测速率代替峰值可作实际参照。报告算力或带宽利用率时给出分子、分母和覆盖范围，以整条时间线判定下一次优化应投入的阶段。改了收缩树、投影或精度后重新统计工作量。
